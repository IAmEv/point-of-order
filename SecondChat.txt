The bug
Round targets are computed as ceil(total/2) and total - round1Target, but the auto-placed proposer (slot 1 if "first", slot N if "last") isn't subtracted from the round they occupy.

For a 6-speaker mod, proposer chose last:

Round 1 target = 3 → correct (proposer isn't in this round, you pick 3)
Round 2 target = 3 → wrong (proposer already occupies slot 6, so only slots 4 and 5 are open — you should only pick 2)
Same class of bug in the mirror case: 6-speaker mod, proposer chose first → Round 1 should only need 2 picks (slots 2, 3), not 3.

Fix
In enterRound1() and enterRound2(), subtract 1 from the target if the proposer is auto-placed in that round:

js
// Round 1
if (state.proposerChoice === 'first') state.round1Target -= 1;

// Round 2
if (state.proposerChoice === 'last') state.round2Target -= 1;
Then add a defensive guard in markSpeakerPicked(): after each pick, check if the round's picked-count has reached the (corrected) target, and if so, advance to the next stage immediately. This also protects against any future off-by-one from another edit.

The dais counter ("Selected X of Y") will now display the corrected Y, so what you see and what the game enforces stay in sync.
